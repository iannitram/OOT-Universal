# G2 synthetic instruction probe

This runs the vendored per-instruction AArch64-to-C emitters from both pinned candidate import commits on project-authored `ADD`, `CBZ`, `STR`, `LDR` and `MOVI v0.4s, #18` encodings. Git reads the two source files from the local Git object database into a temporary directory. Donor source remains in the import branches; this probe commits no donor code. No game copy, image, or generated game code is used. Temporary emitter files and default build outputs are removed after the probe exits. Fetch the import branches first if the pinned commits are not locally available.

Requirements: Python 3, Git, a working host Clang C/C++ toolchain and an AArch64-capable Clang backend. On Windows the C++ toolchain must have a working C++ standard library and linker. Pass explicit executables with `--clang` and `--clangxx` if they are not on PATH. Run from the repository root:

```sh
python tools/probes/g2/probe.py
```

For each candidate, the probe checks the emitter flags and runs the original emitted C natively. It checks ADD normal and wrapping results, both CBZ destinations using a minimal host dispatch, and an eight-byte store/load round trip. The project-authored memory helpers use bounded byte offsets and little-endian encoding, and the fixture checks out-of-bounds reads and writes. The emitted branch sets the guest PC and returns; the host fixture dispatches only its two known destinations.

The vector case checks the full 128-bit destination: each of its four 32-bit lanes must contain `0x00000012`. A small `vreg[32][2]` field supplies the two 64-bit halves expected by the emitted C; a neighboring vector register is seeded and checked unchanged. This is fixture register storage and a result check, not an alternate implementation of MOVI. The probe also compiles the fixture as a freestanding `aarch64-none-elf` object. A nonzero exit indicates failure. Windows x86-64 execution and ARM64 object compilation passed with Python 3.12.10 and Clang 23.1.5 for both candidates.

These five instruction forms do not exercise the full candidate lift pipeline or its host runtime. This single vector-immediate case does not establish broader FP/vector coverage. Realistic guest address mapping, threading/TLS, broad instruction coverage, mobile execution and selected-base compatibility remain open. [Desktop CI](../../../.github/workflows/g2.yml) confirms the host architectures and executes the fixtures on macOS ARM64 and Windows x86-64. The freestanding object compile remains a separate check. The imported emitters contain GPL-licensed code; the probe does not copy it into the repository.

To retain only the generated includes for a cross-platform link check, create an empty directory and run `python tools/probes/g2/probe.py --emit-dir <directory>`. It exports `relink/` and `longshot/` include files after the normal checks; donor source and emitter libraries remain temporary. The [Android workflow](../../../.github/workflows/android-abi.yml) links both fixture variants with the API 24 NDK compiler and verifies their ELF headers and Android interpreter. The [iOS workflow](../../../.github/workflows/ios-abi-link.yml) links device and simulator variants for both candidates and verifies their ARM64 architecture and Mach-O platform. These SDK jobs do not install or execute the mobile binaries.

The same command also runs each pinned `a64_lift.Lifter` against authored branch, direct-call and indirect-call functions. The existing five-instruction branch image remains covered. Separate caller and callee entries verify discovery and the emitted direct-call reference. The indirect caller executes `BLR x16`; the fixture dispatcher checks its target and post-BLR guest link address, invokes the emitted callee only for the expected target, and rejects an unknown target or incorrect site. The callee records its link register, while the caller keeps its incoming link in guest scratch register x9, which the known callee leaves untouched; after a real guest `ADD` following the call, the caller restores its original link and returns. Native checks cover the valid, unknown-target and incorrect-site cases, including results and link registers. The project-owned minimal context supplies the registers needed by these fixtures. The lifter modules, generated functions and executable remain temporary. This establishes only these synthetic functions; general jump tables, game lifting, full runtime integration and selected-base compatibility remain open. The existing desktop workflow runs this check on its Windows x86-64 and macOS ARM64 runners.
